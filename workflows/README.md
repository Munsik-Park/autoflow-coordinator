# 레퍼런스 워크플로우

조율 세션이 회차 워크플로우를 짤 때 출발점으로 쓰는 기본 구성이다. 초안이며, "조율자의 역할과 개념"은 RUNBOOK을 모듈 기준으로 개편할 때 RUNBOOK으로 옮긴다.

## 조율자의 역할과 개념

AutoFlow 모듈은 입력과 목표를 받아 실행하는 부품이다. 조율자는 요청에 맞는 워크플로우를 구성하고, 모듈의 결과를 판단해 다음 모듈의 입력과 목표로 잇는다. 아래 개념은 그 일의 기준이다. 개별 경우의 방법은 계약과 사용법을 읽고 조율자가 찾는다.

- **워크플로우**: 이번 요청에 쓸 묶음과 순서, 세션을 끊는 곳, 품질 목표, 최종 결과물.
- **묶음**: 이슈 해결에서 함께 거쳐야 하는 단계의 모임. 모듈을 나눈 목적은 단계 사이를 조율자가 판단해 넘기게 하는 데 있고, 모듈 하나를 따로 실행하게 하려는 것이 아니다. 조율자가 판단해 묶음 일부만 실행할 수는 있다.
- **연결**: 다음 모듈의 입력은 계약이 가리키는 출처에서 채운다. 앞 실행의 출력이 기본이고, 앞 단계가 없거나 필요한 내용이 출력에 없으면 조율자가 계약 형식에 맞춰 만든다. 모듈은 입력의 형식만 보므로 가능하다. 조율자가 만든 입력은 그 출처를 회차 기록에 남긴다.
- **판정**: 모듈은 목표까지 실행하고 점수나 지적을 낸다. 충분한지는 조율자가 품질 목표에 비추어 판정한다. 출력이 입력에 맞는지, 출력이 적은 사실이 맞는지도 조율자가 확인한다.
- **재진입**: 목표에 못 미치면 원인이 생긴 단계로 돌아가 그 뒤를 다시 실행한다. 돌아간 곳과 근거는 회차 기록에 남긴다. 반복 상한은 두지 않는다. PR을 낸 뒤에 생긴 commit은 delivery와 ci를 다시 거쳐 같은 PR에 반영한다. 주석만 고친 commit은 재채점과 리뷰 round 없이 끝난다(AutoFlow `docs/units/completion-evaluation.md` > Code comments in a target).
- **세션**: 앞 단계와 독립적으로 수행할 수 있으면 새 세션, 이어서 수행해야 하면 한 세션에서 잇는다. 한 세션에서 이을 때도 모듈 사이의 판단은 조율자가 한다. 세션은 모듈 하나를 마치면 멈추고, 조율자가 다음 입력과 목표를 준다. 새 세션에는 앞 출력과 목표만 넘긴다.
- **품질 목표**: 레퍼런스 기본값, workspace의 `coordination.md`(있으면), 회차 지시 순으로 정하고 뒤의 것이 앞의 것을 덮어쓴다. 리뷰의 기본값은 모든 레퍼런스에서 Medium 이상 없음이다. 목표를 모듈에 instructions로 전할 수 있지만 판정은 조율자가 한다.

## 회차에서 고르는 법

요청의 성격과 workspace의 `coordination.md`(있으면)를 보고 레퍼런스를 고르거나 바꾼다(커스텀). 아웃라인(묶음, 세션, 품질 목표, 결과물)을 운영자에게 보여 승인받고, 고른 것과 바꾼 점을 회차 기록에 남긴다. 정의는 이 폴더에만 둔다.

## 경로

회차 자료와 AutoFlow 기록 폴더는 진행 기록인 조율 root 아래에, worktree는 작업 공간인 base 아래 대상 레포의 workspace에 둔다. 조율 root와 base는 설정으로 찾는다([SETTINGS.md](../SETTINGS.md)).
